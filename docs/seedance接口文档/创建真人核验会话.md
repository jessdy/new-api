# 创建真人核验会话

## OpenAPI Specification

```yaml
openapi: 3.0.1
info:
  title: ''
  description: ''
  version: 1.0.0
paths:
  /v1/virtual-characters/validation-sessions:
    post:
      summary: 创建真人核验会话
      deprecated: false
      description: >
        创建真人素材的第一步：为当前 API 用户创建核验会话并预留角色，返回本人认证入口。**本接口返回成功只代表会话创建成功；本人 H5
        认证通过后，还必须上传同一人的肖像并等待素材生效，才能用于视频生成。**


        ### 完整流程


        创建核验会话 → 本人在手机完成 H5 认证 → 查询认证结果 → 上传本人肖像 → 查询素材生效状态 → 引用角色生成视频。


        ### 1. 准备请求并创建会话


        服务地址为 `https://susciyuan.com`。全部 API 请求使用同一用户的 API Key，在请求头携带
        `Authorization: Bearer <API_KEY>`；角色归属于该用户。账号需有可用的真人素材额度，可通过 `GET
        /v1/virtual-characters?scope=private&source_type=volc_real_person` 查看
        `data.real_person_used` 和 `data.real_person_limit`。


        调用本接口 `POST /v1/virtual-characters/validation-sessions`，设置
        `Content-Type: application/json`，按下方参数填写角色名称等信息。例如：


        ```json

        {
          "name": "我的真人角色",
          "description": "本人授权使用的角色",
          "tags": ["真人"],
          "language": "zh"
        }

        ```


        HTTP `200` 后保存以下返回值：


        - `data.id`：核验会话 ID，后续作为路径参数 `{session_id}` 查询认证结果。

        - `data.character_id`：预留角色的数字 ID，后续作为 `{character_id}`
        查询角色、上传肖像及生成视频；不要与会话 ID 混用。

        - `data.launch_url`：本人认证链接，应立即保存；后续查询会话不会重新提供有效链接。

        - `data.expires_at`：会话过期时间，Unix 秒；当前有效期为 30 分钟，以返回值为准。


        ### 2. 由肖像本人完成 H5 认证


        让肖像本人在手机打开 `launch_url`，或由自己的应用将链接转为二维码供本人扫描。本人按 H5
        引导完成身份信息、活体核验和授权步骤，完成后保留正常返回流程，以便系统接收认证结果。


        不要把 API Key 交给扫码人，也不要将认证链接发送给第三方在线二维码服务。手机显示认证成功后，继续查询 API
        状态；此时不能直接认为肖像素材已可用于生成。


        ### 3. 查询认证结果


        调用 `GET /v1/virtual-characters/validation-sessions/{session_id}`，检查
        `data.status`：


        - `pending`：本人尚未完成认证，或认证已通过、素材组结果仍在同步。可间隔约 5 秒继续查询，不要重复创建会话。

        - `succeeded`：认证结果已确认，可以进入肖像上传步骤。

        - `failed`、`expired`、`cancelled`：停止轮询，查看 `data.last_error`，排查后按需重新创建会话。


        未完成认证的预留角色可能不会出现在素材列表中，应以会话查询为准。未完成且不再需要的会话可调用 `DELETE
        /v1/virtual-characters/validation-sessions/{session_id}` 取消。


        ### 4. 上传已核验本人的肖像


        先调用 `GET /v1/virtual-characters/{character_id}`，确认
        `data.validation_status=accepted` 且
        `data.asset_upload_required=true`，再调用 `POST
        /v1/virtual-characters/{character_id}/asset`。


        请求体为 `multipart/form-data`，文件字段名为 `file`，上传与被认证人一致的肖像。由 HTTP 客户端生成
        multipart boundary 和对应请求头。支持 jpg/jpeg/png/webp/gif/heic，最大
        30MB。Bash/cURL 示例（变量替换为自己的 API Key 和角色 ID）：


        ```bash

        curl --request POST \
          "https://susciyuan.com/v1/virtual-characters/${CHARACTER_ID}/asset" \
          --header "Authorization: Bearer ${API_KEY}" \
          --form "file=@./portrait.jpg"
        ```


        HTTP `201` 表示上传已受理，仍需等待素材审核。一个真人素材只能成功提交一张肖像，重复上传返回
        `asset_already_uploaded`。上传超时后先查询角色详情，确认是否已提交成功，再决定是否重试。


        ### 5. 等待素材生效


        继续调用 `GET /v1/virtual-characters/{character_id}`；需要主动刷新时调用 `POST
        /v1/virtual-characters/{character_id}/sync`。可从 5 秒间隔开始查询，等待较久时适当增加间隔。


        只有以下条件全部满足，才继续创建视频：


        - `data.status=active`。

        - `data.validation_status=accepted`。

        - `data.authorization.status=active`。

        - `data.provider_asset_id` 非空。


        `asset_upload_required=true` 表示还需要上传照片，不能仅凭 `status=creating`
        判断正在审核。上传后该字段可能省略，省略也不代表素材已生效。失败时查看 `data.last_error` 和
        `data.authorization.last_error`。


        ### 6. 引用角色生成视频并查询结果


        调用 `POST /v1/videos`，将已生效角色的数字 ID 填入 JSON 字段 `character_id`，例如：


        ```json

        {
          "model": "AP Seedance-2.5 标准版",
          "character_id": 123,
          "prompt": "人物面向镜头自然微笑并轻轻挥手。",
          "resolution": "480p",
          "ratio": "16:9",
          "duration": 4,
          "generate_audio": false
        }

        ```


        将 `123` 替换为自己的角色 ID；使用 `character_id`
        时不要同时提供其他图片、视频或音频参考素材。模型、规格和价格以账号当前可用项及 `GET /api/pricing` 为准，生成视频会计费。


        HTTP `202` 后保存响应顶层 `id` 为 `{task_id}`，调用 `GET /v1/videos/{task_id}`
        查询。状态为 `completed` 时读取 `metadata.url`，或通过带 Bearer 鉴权的 `GET
        /v1/videos/{task_id}/content` 获取视频；失败时读取任务错误并停止轮询。


        若改用官方兼容接口，则通过 `POST /api/v3/contents/generations/tasks`
        创建，并使用对应查询路径，成功状态为 `succeeded`。用哪个协议创建，就用对应协议查询。


        **流程判断要点：会话创建成功 ≠ 本人认证通过 ≠ 肖像素材生效 ≠ 视频生成完成。**
        每一步都应根据对应接口的状态继续。素材已生效但视频创建失败时，保留请求时间和错误响应排查，不要因此重新认证或重复上传。
